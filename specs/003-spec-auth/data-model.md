# Data Model: Customer Sign-In for the Support Chat

Account data is stored in PostgreSQL (research.md R11). Chat sessions, messages, and feedback stay in memory (research.md R9). Passwords and tokens are never stored in plain text: passwords as BCrypt hashes, tokens as SHA-256 hashes (R3). All timestamps are UTC.

## Account

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | Generated by the server. Not placed in URLs. Returned only to its owner (`GET /api/auth/me`). |
| `email` | text, up to 254 | Stored lowercase and trimmed. Unique. Required. |
| `password_hash` | text | BCrypt hash. Never returned, never logged. |
| `email_verified_at` | timestamp, nullable | Set once, when the verification link is used. Verification is one-way. |
| `created_at` | timestamp | Set on creation. |
| `last_sign_in_at` | timestamp, nullable | Set on each successful sign-in. Drives the 30-day inactivity rule (FR-023). |

**Validation**: email must be a syntactically valid address. Password rules: at least 12 characters, at most 72 bytes, not on the breached list (R2, R6). A new account starts unverified.

**State**: `unverified` → `verified` (on the first verification). There is no path back. Deleted by the retention job (R8).

## VerificationToken

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | Server-generated. |
| `account_id` | UUID | Foreign key to Account, cascade delete. |
| `token_hash` | text | SHA-256 of the random token. Unique. The plain token exists only in the email. |
| `created_at` | timestamp | |
| `expires_at` | timestamp | `created_at` + 24 hours (FR-004). |
| `used_at` | timestamp, nullable | Set when the link is used, or when a newer token supersedes it (FR-005). |

**State**: `active` → `used` (confirmed) or `superseded` (a new one was sent; `used_at` is set) or `expired` (past `expires_at`). Only `active` and unexpired tokens are accepted.

## PasswordResetToken

Same shape as VerificationToken, with `expires_at` = `created_at` + 30 minutes (FR-014).

**State**: `active` → `used` (password set). Requesting a new reset supersedes earlier active tokens for the same account. Only one is valid at a time.

## AuthSession

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | Carried in the access credential as the session claim. |
| `account_id` | UUID | Foreign key to Account, cascade delete. |
| `created_at` | timestamp | |
| `signed_in_at` | timestamp | Set when the customer enters their password to create this session. Starts the 30-day cap. A password reset does not create a session. |
| `max_expires_at` | timestamp | `signed_in_at` + 30 days (FR-009). Never extended. |
| `last_activity_at` | timestamp | Written at most once a minute (R3). A session idle for 15 minutes is expired. |
| `revoked_at` | timestamp, nullable | Set on sign-out, password reset, or reuse detection. |
| `revoke_reason` | enum, nullable | `SIGNED_OUT`, `PASSWORD_RESET`, `REFRESH_REUSE`. |

**State**: `active` → `revoked` (by sign-out, reset, or reuse) or `expired` (idle over 15 minutes, or past `max_expires_at`). Expired sessions are not revoked explicitly. They simply fail the check. A password reset revokes every active session for the account (AUTH-16).

**Access rule**: a request is authenticated only if its credential is valid, and its session is `active`, not idle past 15 minutes, and before `max_expires_at`.

## RefreshToken

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | |
| `session_id` | UUID | Foreign key to AuthSession, cascade delete. |
| `token_hash` | text | SHA-256 of the random value. Unique. |
| `issued_at` | timestamp | |
| `used_at` | timestamp, nullable | Set when rotated. A second use of a rotated value revokes the session (`REFRESH_REUSE`). |

**State**: `active` → `used` (rotated, replaced by a new token in the same session).

## Chat Session (in memory, changed)

Existing `Session` (001 data model) gains one field:

| Field | Type | Rules |
|-------|------|-------|
| `ownerAccountId` | UUID | Set when a signed-in customer creates the session. Every read and write checks it. Non-owners get 404 (AUTH-6). |

Existing rules otherwise unchanged: 30-minute idle expiry, held in memory, not persisted.

## Escalation Ticket Payload (changed)

Existing `TicketPayload` (001 data model) gains:

| Field | Type | Rules |
|-------|------|-------|
| `accountId` | UUID | Required for every escalation (AUTH-10). |
| `customerEmail` | text | Required (AUTH-10). Sent to the ticketing system. Never logged (T-L1). |

The payload still does not include the full transcript (001 plan, Principle V).

## Relationships

- One Account has many VerificationToken, PasswordResetToken, and AuthSession records.
- One AuthSession has many RefreshToken records (in practice one active at a time, because of rotation).
- One Account owns many in-memory chat Sessions (`ownerAccountId`).

## Retention (FR-023, research.md R8)

- An Account with no successful sign-in for 30 days is deleted, and its tokens, sessions, and refresh credentials go with it through cascades. For an account never signed in, the 30 days run from `created_at`.
- In-memory chat sessions owned by a deleted account are dropped at the same time.
- Expired tokens and sessions are deleted by the same daily job once they are past their useful life.
